# FPGA Export Tutorial (HLS)

This tutorial shows how to export a trained bio-plausible kernel to an FPGA-ready HLS (High-Level Synthesis) project using the `biopl-export-trained-kernel` CLI.

## Prerequisites

- Python 3.14+ with `uv` package manager
- Trained model checkpoint (or train from scratch)
- AMD Vitis HLS / Xilinx Vivado HLS for synthesis
- Target FPGA board (e.g., Xilinx Alveo U250, U280, or Zynq UltraScale+)

## Quick Start

```bash
# Train and export a Feedback Alignment kernel to HLS
uv run biopl-export-trained-kernel \
    --algorithm fa \
    --target cpu \
    --epochs 20 \
    --dataset mnist \
    --precision fp16 \
    --output ./fa_hls_project \
    --format hls
```

## Supported Algorithms for FPGA Export

| Algorithm | Kernel Backend | HLS Support | Notes |
|-----------|----------------|-------------|-------|
| `fa` | `FAKernelBackend` | ✅ Full | Best suited for FPGA |
| `hebbian` | `HebbianKernelBackend` | ✅ Full | Outer product maps to DSP |
| `ff` | `FFKernelBackend` | ✅ Full | Goodness = L2 norm |
| `tp` | `TPKernelBackend` | ⚠️ Partial | Inverse net needs BRAM |
| `pc` | `PCKernelBackend` | ⚠️ Partial | Iterative inference |
| `mep` | `MEPKernelBackend` | ⚠️ Partial | Muon needs SVD |
| `eqprop` | `EqPropKernelBackend` | ✅ Full | Settling loop unrolls |
| `backprop` | `BackpropKernelBackend` | ✅ Full | Standard baseline |

## Step-by-Step Workflow

### 1. Train the Model

The CLI trains the model automatically, but you can also use a pre-trained checkpoint:

```bash
# From scratch (auto-trains)
uv run biopl-export-trained-kernel \
    --algorithm fa \
    --target cpu \
    --epochs 30 \
    --dataset mnist \
    --output ./fa_hls

# With checkpoint
uv run biopl-export-trained-kernel \
    --algorithm fa \
    --target cpu \
    --checkpoint ./fa_checkpoint.pt \
    --output ./fa_hls
```

### 2. Export Configuration

Key parameters:
- `--precision`: `fp32`, `fp16`, `bf16` (FP16 recommended for FPGA)
- `--format`: `hls`, `verilog`, `onnx` (default: `hls`)
- `--hls-target`: Target FPGA part (e.g., `xcu250-figd2104-2L-e`)

```bash
# Full precision control
uv run biopl-export-trained-kernel \
    --algorithm fa \
    --target triton \
    --epochs 20 \
    --precision fp16 \
    --format hls \
    --hls-target xcu250-figd2104-2L-e \
    --output ./fa_u250_hls
```

### 3. Generated HLS Project Structure

```
fa_hls_project/
├── kernel_hls.cpp          # HLS kernel source
├── kernel_hls.h            # Header with pragmas
├── kernel_tb.cpp           # Testbench
├── run_hls.tcl             # Vitis HLS run script
├── manifest.json           # Kernel metadata
├── state_dict.pt           # Trained weights
├── export_summary.json     # Export statistics
└── README.md               # Build instructions
```

### 4. Synthesize with Vitis HLS

```bash
cd fa_hls_project

# Run HLS synthesis
vitis_hls -f run_hls.tcl

# Or manually in Vitis HLS GUI:
# 1. File > New Project
# 2. Add kernel_hls.cpp, kernel_hls.h, kernel_tb.cpp
# 3. Set target device (e.g., xcu250-figd2104-2L-e)
# 4. Run C Synthesis > Export RTL
```

### 5. Vitis HLS TCL Script (run_hls.tcl)

```tcl
# Auto-generated by biopl-export-trained-kernel
open_project fa_hls
add_files kernel_hls.cpp kernel_hls.h
add_files -tb kernel_tb.cpp
set_top kernel_fa_forward
open_solution "solution1" -flow_target vitis
set_part {xcu250-figd2104-2L-e}
create_clock -period 3.33 -name default
csynth_design
export_design -format ip_catalog
```

## Kernel HLS Code Structure

The exported HLS kernel follows this pattern:

```cpp
// kernel_hls.h
#ifndef KERNEL_FA_H
#define KERNEL_FA_H

#include <ap_fixed.h>
#include <hls_stream.h>

// Fixed-point types for FPGA
typedef ap_fixed<16, 6> data_t;    // FP16 equivalent
typedef ap_fixed<32, 16> acc_t;    // Accumulator

// Layer dimensions (from trained model)
#define INPUT_DIM 784
#define HIDDEN_DIM 256
#define OUTPUT_DIM 10

void kernel_fa_forward(
    const data_t input[INPUT_DIM],
    data_t output[OUTPUT_DIM],
    const data_t W1[HIDDEN_DIM][INPUT_DIM],
    const data_t b1[HIDDEN_DIM],
    const data_t W2[OUTPUT_DIM][HIDDEN_DIM],
    const data_t b2[OUTPUT_DIM],
    const data_t B_fb[HIDDEN_DIM][OUTPUT_DIM]  // Fixed feedback
);

#endif
```

```cpp
// kernel_hls.cpp
#include "kernel_hls.h"

void kernel_fa_forward(
    const data_t input[INPUT_DIM],
    data_t output[OUTPUT_DIM],
    const data_t W1[HIDDEN_DIM][INPUT_DIM],
    const data_t b1[HIDDEN_DIM],
    const data_t W2[OUTPUT_DIM][HIDDEN_DIM],
    const data_t b2[OUTPUT_DIM],
    const data_t B_fb[HIDDEN_DIM][OUTPUT_DIM]
) {
    // Hidden layer computation
    data_t hidden[HIDDEN_DIM];
    #pragma HLS ARRAY_PARTITION variable=hidden cyclic factor=4
    #pragma HLS PIPELINE II=1

    for (int j = 0; j < HIDDEN_DIM; j++) {
        acc_t sum = b1[j];
        for (int i = 0; i < INPUT_DIM; i++) {
            sum += input[i] * W1[j][i];
        }
        hidden[j] = (sum > 0) ? sum : 0;  // ReLU
    }

    // Feedback alignment (fixed random backward)
    data_t feedback[HIDDEN_DIM];
    #pragma HLS ARRAY_PARTITION variable=feedback cyclic factor=4

    // ... feedback computation ...

    // Output layer
    for (int k = 0; k < OUTPUT_DIM; k++) {
        acc_t sum = b2[k];
        for (int j = 0; j < HIDDEN_DIM; j++) {
            sum += hidden[j] * W2[k][j];
        }
        output[k] = sum;
    }
}
```

## Precision Mapping

| PyTorch | HLS Type | Bits | Int/Frac |
|---------|----------|------|----------|
| `float32` | `float` | 32 | N/A |
| `float16` | `ap_fixed<16,6>` | 16 | 6/10 |
| `bfloat16` | `ap_fixed<16,8>` | 16 | 8/8 |
| `int8` | `ap_int<8>` | 8 | 8/0 |

**Recommendation:** Use `fp16` with `ap_fixed<16,6>` for best DSP utilization.

## Advanced: Custom HLS Pragmas

Add custom pragmas via export config:

```python
# In your training script before export
from bioplausible.acceleration.export import export_kernel_to_hls
from bioplausible.core.acceleration.kernel_backend import KernelConfig, AlgorithmFamily, HardwareTarget
import torch

config = KernelConfig(
    algorithm=AlgorithmFamily.FEEDBACK_ALIGNMENT,
    hardware=HardwareTarget.FPGA,
    dtype=torch.float16,
    extra={
        "hls_pipeline_ii": 1,
        "hls_array_partition": "cyclic",
        "hls_partition_factor": 4,
        "hls_unroll_factor": 4,
    }
)

export_kernel_to_hls(kernel_backend, config, Path("./custom_hls"))
```

## Troubleshooting

### "Precision loss in HLS synthesis"
- Increase integer bits: `ap_fixed<16,7>` or `ap_fixed<18,7>`
- Check weight ranges in `export_summary.json`

### "Timing violation at 300MHz"
- Reduce pipeline II: `#pragma HLS PIPELINE II=2`
- Increase clock period in TCL: `create_clock -period 5.0`

### "BRAM overflow"
- Reduce batch size in testbench
- Use `hls::stream` for streaming interfaces

### "Feedback weights don't match"
- Ensure `--target cpu` during export (FA feedback is fixed random)
- Check `manifest.json` for feedback weight stats

## Complete Example: End-to-End FA on Alveo U250

```bash
# 1. Train & export
uv run biopl-export-trained-kernel \
    --algorithm fa \
    --target cpu \
    --epochs 30 \
    --dataset mnist \
    --precision fp16 \
    --hls-target xcu250-figd2104-2L-e \
    --output ./fa_u250_mnist

# 2. Synthesize
cd fa_u250_mnist
vitis_hls -f run_hls.tcl

# 3. Check reports
cat solution1/syn/report/kernel_fa_forward_csynth.rpt

# 4. Export RTL
vitis_hls -f run_hls.tcl export_design -format ip_catalog
```
