**Codebase**: 316 Python files, ~41K lines.
**Sprint 2.4 — Benchmarks + Reproducibility Relocations**: ✅ **Done** — plan complete (see status table).
**Goal**: Maximize size reduction via deduplication, DRY, and structural consolidation — *without* weakening the two model hierarchies (`BioModel` eqprop/pc/fa/hebbian and the `TileAlgorithm` tile substrate) or the `equitile/`-subsumption end-state.
**Method**: Each change lands a single canonical helper/constant and migrates call sites in the same pass; verification via zero-diff recipe (`git stash` → ruff → pyright → targeted `pytest --no-cov`).

  - **Metrics reconciliation direction**: the reader audit showed the `_accuracy`/`_acc` families were disjoint (no shared join), so either direction was behaviorally safe. Chose to rename `TrainingMetrics` → `_acc` because `_acc` is the majority convention (used by `EpochCheckpoint`/`EpochMetrics`/`BenchmarkMetrics` — 3 of 4 epoch-level containers) and `EpochCheckpoint` is the canonical epoch record. **Scope-boundary pitfall**: `val_accuracy`/`train_accuracy` appear in ~50 places but only ~15 are the `TrainingMetrics` dataclass field; the rest are dict-key/DataFrame/serialization contracts (trainer `_validate` dict, `domains/trainer.py`, `experiments/utils.py`, `visualization.py`, `continual_learning.py`, `ablation.py`, `scaling.py`, `knowledge/kb.py`, `autoscientist/reasoner.py`) that must NOT be renamed (they key on persisted dicts consumed by `phase2_autoscientist`/`test_knowledge`/`reasoner`). So merging into `training_checkpoints` (with `trajectory_id=-1` for streamed rows, matching `CheckpointManager.flush`) loses no live functionality. `get_all_trajectories`/`synthesizer._load_convergence_data` filter on real `trajectory_id` values, so the `-1` streaming rows don't collide.
